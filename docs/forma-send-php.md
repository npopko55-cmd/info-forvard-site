# Форма заявок → send.php (РФ-хостинг, 152-ФЗ)

После переезда на reg.ru форма шлёт заявки на **свой же РФ-сервер** (`/send.php`),
оттуда — письмом на РФ-почту. Google (Apps Script + Таблица) из схемы убран полностью:
персональные данные за границу не уходят → локализация по 152-ФЗ ст. 18 ч. 5 выполнена.

```
Форма → POST /send.php (reg.ru, РФ) → письмо на РФ-ящик
```

## Файлы

- `public/send.php` — принимает заявку, валидирует (телефон, согласие, honeypot), шлёт письмо по SMTP.
  После сборки лежит в корне сайта как `send.php`.
- `public/config.local.example.php` — шаблон настроек (без секретов).
- `config.local.php` — **создаётся на сервере**, содержит SMTP-логин/пароль. В git НЕ хранится.

## Настройка на сервере (reg.ru / ISPmanager)

### 1. Почтовый ящик-отправитель (РФ)
Вариант «как в плейбуке» — почта на домене сайта в reg.ru:
1. ISPmanager → **Почта → Почтовые домены** → создать домен `info-forvard.ru` (это доменное имя, не ящик).
2. Создать ящик-отправитель, напр. `zayavka@info-forvard.ru`, задать пароль.
3. Включить **DKIM** и **DMARC** для домена (в разделе почтового домена). SPF обычно ставится сам
   (`include:_spf.hosting.reg.ru`).

> Получатель заявок (`to`) — тоже РФ-ящик (Яндекс 360 / reg.ru / Mail.ru). **НЕ Gmail** —
> иначе данные снова уходят за рубеж и смысл переезда теряется.

### 2. Конфиг с паролем
В менеджере файлов, в корне сайта (рядом с `send.php`):
1. Скопировать `config.local.example.php` → назвать `config.local.php`.
2. Вписать `smtp_host`, `smtp_port` (465), `smtp_user`, `smtp_pass` (**пароль приложения**, не основной),
   `from`, `to`.

### 3. Проверка (без спама себе на почту)
```bash
# GET → 405 (значит PHP распарсился и работает)
curl -sSk --resolve info-forvard.ru:443:<IP> https://info-forvard.ru/send.php
# honeypot → success, письмо НЕ отправляется
curl -sSk -X POST -H 'Content-Type: application/json' \
  -d '{"botcheck":"x"}' https://info-forvard.ru/send.php
# без телефона → 400
curl -sSk -X POST -H 'Content-Type: application/json' \
  -d '{"consent":"да"}' https://info-forvard.ru/send.php
```
Затем — одна настоящая заявка через сайт → письмо должно прийти (проверь и «Спам»:
первое письмо с нового домена провайдер может придержать/положить в спам — нажми «Не спам»).

## Грабли доставки
- `mail()` не используем — на шаред-хостинге доставка к Яндекс/Mail.ru слабая. Шлём по SMTP с авторизацией.
- DKIM/SPF работают только когда DNS домена уже публичны (после пропагации `.ru`). Пока зона не разошлась —
  письмо может уходить в спам или дропаться.
- Порт 465 — implicit SSL (в `send.php` уже так). Если провайдер требует 587/STARTTLS — скажи, добавлю ветку.
